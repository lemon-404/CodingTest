# 공원 — 코딩테스트 풀이 기록

| 항목 | 내용 |
|---|---|
| 문제 등급 | Level 1 |
| 문제 플랫폼 | 프로그래머스 |
| 문제 이름 | 공원 / 340198 |
| 알고리즘 | 완전 탐색, 구현 |
| 입력 | `int[] mats`, `String[][] park` |
| 시간 복잡도 | O(M log M + M × R × C × S²) — 정렬 포함 |
| 예외 케이스 | 배치 가능한 돗자리 없음, 돗자리가 공원 크기를 초과함 |
| 풀이 상태 | 직접 구현 미완성, 정답 참고 |

**문제 정의**

1. `mats`에 정사각형 돗자리의 한 변 길이 제공
2. 공원의 자리 배치도 `park`에서 `"-1"`은 빈 공간을 의미
3. 배치 가능한 돗자리 중 가장 큰 한 변의 길이 반환
4. 배치 가능한 돗자리가 없으면 -1 반환

**엣지 케이스**

- 배치 가능한 돗자리가 없으면 -1 반환
- 돗자리 크기가 공원의 행 또는 열 크기를 초과하면 검사 제외

## 1. 초기 풀이

**접근 방법:**

- 공원의 모든 좌표를 순회하며 돗자리 배치 가능 여부를 판단하는 방식 구상
- 현재 좌표에서 가로·세로 방향의 연속된 빈 공간을 각각 계산
- 가로·세로 길이를 별도로 관리하여 정사각형 구성 여부 판단 시도
- 정사각형 내부 검사에 추가 이중 반복문을 사용하는 방식 고려
- 가장 큰 정사각형 크기를 구한 뒤 `mats`와 비교하여 반환하는 방식 구상
- 반복문 구조를 정리하지 못하여 의사코드·구현 미완성

## 2. 문제 및 성능 분석

**발생한 문제:**

- 필요한 조건은 파악했지만 하나의 탐색 구조로 연결하지 못하여 구현 미완성

**문제를 풀기 위해 사전에 파악한 조건:**

1. 공원의 모든 좌표에서 배치 시작점 탐색 필요
2. 정사각형 내부의 모든 칸이 비어 있는지 확인 필요
3. 검사 영역의 가로·세로 길이는 돗자리 한 변의 길이와 동일
4. 내부 검사는 공원 전체가 아닌 돗자리 크기만큼 수행
5. 가장 큰 돗자리부터 검사하면 배치 가능한 크기를 찾는 즉시 종료 가능
6. 공원 범위를 벗어나는 돗자리는 검사 제외 가능

**문제를 풀지 못한 원인:**

- 가로·세로 방향의 연속된 빈 공간을 각각 계산하는 방식에 집중
- 빈 공간의 시작 좌표·연속 개수·가로 길이·세로 길이를 별도로 관리하려 하면서 구현 복잡화
- 돗자리 크기가 이미 `mats`로 주어졌다는 조건을 탐색의 출발점으로 활용하지 못함
- 돗자리 크기를 먼저 선택한 뒤 시작 좌표와 내부 영역을 검사하는 순서로 단순화하지 못함

**정답을 참고하여 확인한 접근:**

- 가장 큰 돗자리부터 선택
- 해당 돗자리가 들어갈 수 있는 시작 좌표만 탐색
- 시작 좌표에서 돗자리 크기만큼의 정사각형 내부를 이중 반복문으로 검사
- 내부가 모두 빈 공간이면 현재 돗자리 크기 반환

**복잡도:**

- `M`: 돗자리 개수
- `R`: 공원의 행 개수
- `C`: 공원의 열 개수
- `S`: 가장 큰 돗자리의 한 변 길이
- 초기 풀이: 구현 미완성으로 시간 복잡도 확정 불가
- 최종 풀이 정렬: O(M log M)
- 최종 풀이 탐색: O(M × R × C × S²)
- 정렬을 포함한 전체 시간 복잡도: O(M log M + M × R × C × S²)

**최종 의사코드**

- `mats` 배열을 오름차순으로 정렬한다.
- `park`의 행과 열 길이를 각각 `rows`, `cols`에 저장한다.
- `m`은 `mats.length - 1`부터 0 이상인 동안 1씩 감소하며 아래 작업을 반복한다.
  - 현재 돗자리 크기 `mats[m]`을 `size`에 저장한다.
  - `i`는 0부터 `rows - size` 이하까지 1씩 증가하며 아래 작업을 반복한다.
    - `j`는 0부터 `cols - size` 이하까지 1씩 증가하며 아래 작업을 반복한다.
      - 배치 가능 여부를 나타내는 `possible`을 `true`로 초기화한다.
      - `k`는 0부터 `size` 미만까지 1씩 증가하며 아래 작업을 반복한다.
        - `h`는 0부터 `size` 미만까지 1씩 증가하며 아래 작업을 반복한다.
          - `park[i + k][j + h]`가 `"-1"`이 아니면 `possible`을 `false`로 변경하고 `h` 반복문을 종료한다.
        - `possible`이 `false`이면 `k` 반복문을 종료한다.
      - `possible`이 `true`이면 `size`를 반환한다.
- 배치 가능한 돗자리가 없으면 -1을 반환한다.

## 3. 최종 수정 코드

```java
import java.util.Arrays;

public class Park {
    public int solution(int[] mats, String[][] park) {
        Arrays.sort(mats);

        int rows = park.length;
        int cols = park[0].length;

        // 가장 큰 돗자리부터 검사
        for (int m = mats.length - 1; m >= 0; m--) {
            int size = mats[m];

            // 돗자리를 놓을 시작 좌표 탐색
            for (int i = 0; i <= rows - size; i++) {
                for (int j = 0; j <= cols - size; j++) {
                    boolean possible = true;

                    // 정사각형 내부의 모든 칸 검사
                    for (int k = 0; k < size; k++) {
                        for (int h = 0; h < size; h++) {
                            if (!park[i + k][j + h].equals("-1")) {
                                possible = false;
                                break;
                            }
                        }

                        if (!possible) break;
                    }

                    // 배치 가능한 가장 큰 돗자리 반환
                    if (possible) {
                        return size;
                    }
                }
            }
        }

        return -1;
    }
}

```
