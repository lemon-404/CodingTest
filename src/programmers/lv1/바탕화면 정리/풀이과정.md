| 항목 | 내용 |

| 알고리즘 | 2차원 배열 순회, 최솟값·최댓값 갱신 |

| 추가 공간 복잡도 | O(N × M) |

## 문제 정의

1. `wallpaper`는 바탕화면의 파일(`#`)과 빈칸(`.`)을 나타내는 문자열 배열이다.
2. 시작점 S(`lux`, `luy`)에서 끝점 E(`rdx`, `rdy`)까지 한 번 드래그하며, 이동 거리는 `(rdx - lux) + (rdy - luy)`이다.
3. 모든 파일을 포함하면서 이동 거리가 최소인 드래그 시작점과 끝점 `[lux, luy, rdx, rdy]`를 구한다.

## 엣지 케이스

- 파일이 한 개만 있는 경우에도 끝점은 파일의 행·열 좌표에 각각 `+1`이 필요하다.
- 파일이 마지막 행 또는 마지막 열에 있더라도 반복문은 배열의 유효 인덱스까지만 순회한다.
- 파일이 서로 대각선으로 떨어져 있으면 최소 행과 최소 열, 최대 행과 최대 열이 서로 다른 파일에서 나올 수 있다. 각 좌표를 독립적으로 비교해야 한다.
- 파일이 같은 행 또는 같은 열에만 존재하는 경우에도 드래그 영역에 높이 또는 너비 1이 포함되어야 한다.
- 파일이 화면 전체에 존재할 때 끝점은 배열의 행 개수와 열 개수가 될 수 있다.

## 1. 초기 풀이

### 접근 방법

`wallpaper`의 각 문자열을 `split("")`으로 분리하여 2차원 배열에 저장한다.

S를 `(행 개수, 열 개수)`, E를 `(0, 0)`으로 초기화한 후 이중 반복문으로 `#`을 찾는다.

발견한 파일의 행·열 좌표를 S와 E에 각각 비교해 최솟값과 최댓값을 갱신한다.

초기 구상에서는 파일의 오른쪽 아래 경계를 포함하기 위해 이중 반복문의 조건을 `<=`로 설정하려 했다. 이는 아직 실행한 초기 코드가 아닌 설계 단계의 구상이다.

```java
// 초기 구상에서 문제가 되었던 반복 조건
// 실행 코드가 아닌 예시
for (int i = 0; i <= coordinates.length; i++) {
    for (int j = 0; j <= coordinates[i].length; j++) {
        // ...
    }
}
```

## 2. 문제 및 성능 분석

### 발생한 문제

반복문 경계 조건을 `<=`로 설정하면 배열 범위를 벗어날 수 있다. 설계 검토에서 발견한 문제이며, 실제 실행 오류 기록은 없다.

### 원인

길이가 N인 배열의 유효 인덱스는 `0`부터 `N - 1`까지다.

드래그 끝점의 `+1`은 배열 접근 범위를 늘리는 것이 아니라, 파일이 차지하는 칸의 바깥 경계 좌표를 계산하기 위한 것이다.

### 복잡도

N을 행 개수, M을 열 개수라고 할 때, 문자열을 분리해 2차원 배열에 저장하는 데 O(N × M), 모든 칸을 순회하는 데 O(N × M)이 필요하다.

따라서 전체 시간 복잡도는 O(N × M), 추가 공간 복잡도는 O(N × M)이다.

### 개선 방향

반복 조건은 `<`로 유지하고, E의 행·열 좌표를 비교하고 갱신할 때 `i + 1`, `j + 1`을 사용한다.

S와 E의 행·열은 각각 독립적으로 비교한다.

## 3. 최종 수정 코드

```java
public class DesktopCleanup {
    public int[] solution(String[] wallpaper) {
        // 1. 문자열 배열을 2차원 배열로 변환
        String[][] coordinates = new String[wallpaper.length][wallpaper[0].length()];

        for (int i = 0; i < wallpaper.length; i++) {
            coordinates[i] = wallpaper[i].split("");
        }

        // 2. 시작점 S와 끝점 E 초기화
        int[] s = {coordinates.length, coordinates[0].length};
        int[] e = {0, 0};

        // 3. 파일 위치를 순회하며 좌표 갱신
        for (int i = 0; i < coordinates.length; i++) {
            for (int j = 0; j < coordinates[i].length; j++) {
                if (coordinates[i][j].equals("#")) {
                    // 시작점 S: 최소 행, 최소 열
                    if (i < s[0]) s[0] = i;
                    if (j < s[1]) s[1] = j;

                    // 끝점 E: 파일 칸의 바깥 경계 포함
                    if (i + 1 > e[0]) e[0] = i + 1;
                    if (j + 1 > e[1]) e[1] = j + 1;
                }
            }
        }

        // 4. 결과 반환
        int[] answer = {s[0], s[1], e[0], e[1]};
        return answer;
    }
}
```

## 4. 개선 결과

| 구분 | 초기 설계 | 수정 코드 |
| --- | --- | --- |
| 주요 접근 | 2차원 배열 순회 및 좌표 갱신, 반복문 `<=` 구상 | 2차원 배열 순회 및 좌표 갱신, 반복문 `<`와 E 좌표 `+1` |
| 시간 복잡도 | O(N × M) 의도(경계 오류 가능) | O(N × M) |
| 추가 공간 복잡도 | O(N × M) | O(N × M) |

### 학습 내용

- 배열의 유효 인덱스와 파일 칸의 바깥 경계 좌표를 구분해야 한다.
- 추가 공간을 줄이려면 별도의 2차원 배열을 만들지 않고 `wallpaper[i].charAt(j)`로 직접 접근하는 방법도 있다. 이 경우 추가 공간 복잡도를 O(1)로 줄일 수 있다.
