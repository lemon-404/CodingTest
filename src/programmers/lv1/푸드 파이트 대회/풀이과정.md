# 푸드 파이트 대회 — 코딩테스트 풀이 기록

| 항목     | 내용                             |
| ------ | ------------------------------ |
| 문제 등급  | Lv.1                           |
| 문제 플랫폼 | 프로그래머스                         |
| 문제 이름  | 푸드 파이트 대회 (134240)             |
| 알고리즘   | 구현, 시뮬레이션                      |
| 입력     | `int[] food`                   |
| 시간 복잡도 | 1차 개선 O(N + M) → 최종 O(N + M)   |
| 예외 케이스 | 음식의 개수가 홀수인 경우, 음식의 개수가 1개인 경우 |

**문제 정의**

1. 매 대결마다 음식의 종류와 양이 바뀐다.
2. 준비된 음식은 일렬로 배치하되, 한 선수는 왼쪽부터, 다른 선수는 오른쪽부터 순서대로 먹는다.
3. 중앙에는 항상 물을 배치한다.
4. 칼로리가 낮은 음식부터 먹을 수 있도록 배치한다.
5. 초과 준비된 음식은 사용하지 않는다.

**핵심 조건**

1. 음식의 섭취 순서는 칼로리 기준 오름차순이다.
2. 두 선수는 동일한 종류의 음식을 먹어야 한다.
3. 두 선수는 동일한 양의 음식을 먹어야 한다.
4. 두 선수는 동일한 순서로 음식을 먹을 수 있어야 한다.
5. 중앙에는 항상 물을 배치한다.

**엣지 케이스**

- 음식의 개수가 홀수인 경우
  - 동일하게 분배할 수 있는 만큼 사용하고 나머지는 사용하지 않는다.
- 음식의 개수가 1개인 경우
  - 동일하게 분배할 수 없으므로 사용하지 않는다.

**의사코드**

1. 정수형 배열 `line`을 선언하고 초기화한다.
   - 배열의 길이는 `food.length - 2`로 설정한다.
   - 정수형 배열의 기본 초기화 값은 0이므로 별도로 초기화하지 않는다.
2. `line` 배열의 삽입 위치를 관리할 정수형 변수 `l`을 0으로 초기화한다.
3. `i`는 1부터 `food.length` 미만일 때까지 아래 내용을 반복한다. `i`는 1씩 증가한다.
   - `food[i]`를 정수형 변수 `qt`에 저장한다.
   - `qt`가 2로 나누어떨어지지 않는 경우
     - `qt`에서 1을 빼고 갱신한다.
   - `j`는 0부터 `qt` 미만일 때까지 아래 내용을 반복한다. `j`는 1씩 증가한다.
     - `j`가 홀수인 경우
       - `line[l]`에 `i`를 삽입한다.
     - `j`가 짝수인 경우
       - `line[line.length - 1 - l]`에 `i`를 삽입한다.
       - `l`을 1 증가시킨다.
4. `line` 배열을 `String`으로 변환하여 반환한다.

## 1. 초기 풀이

**접근 방법**

**첫 번째 구상 — 중앙 기준 삽입 방식**

- 물을 중심으로 칼로리가 높은 음식부터 배치한다.
- 기준점을 중심으로 왼쪽과 오른쪽에 음식을 하나씩 번갈아 배치한다.
- 기준점보다 앞에 문자를 삽입하기 위해 배열 또는 `StringBuilder.insert()`를 사용하는 방법을 고려했다.
- `StringBuilder`는 내부적으로 배열을 사용하기 때문에 삽입 위치 이후의 원소를 뒤로 이동시켜야 한다.
- 따라서 `insert()`의 최악의 시간 복잡도가 O(N)이므로 해당 방식을 채택하지 않았다.

**두 번째 구상 — 총량 길이 배열 삽입 방식 (채택)**

- 푸드 파이트 대회에서 사용될 음식의 총량을 미리 계산할 수 있다.
- 사용될 음식의 총량을 기준으로 배열을 미리 선언한다.
- 배열의 왼쪽과 오른쪽 인덱스에 직접 음식 번호를 삽입한다.
- 정수형 배열은 모든 원소가 기본적으로 0으로 초기화되므로 중앙에 물을 별도로 삽입하지 않는다.

```java
import java.util.Arrays;
import java.util.stream.Collectors;

public class FoodFightCompetition {
    public String solution(int[] food) {
        int[] line = new int[food.length - 2];
        int l = 0;

        for (int i = 1; i < food.length; i++) {
            int qt = food[i];

            if (qt % 2 != 0) {
                qt -= 1;
            }

            for (int j = 0; j < qt; j++) {
                if (j % 2 != 0) {
                    line[l] = i;
                } else {
                    line[line.length - 1 - l] = i;
                    l++;
                }
            }
        }

        return Arrays.stream(line)
                .mapToObj(String::valueOf)
                .collect(Collectors.joining());
    }
}
```

## 2. 문제

**발생한 문제**

1. **배열 길이 초기화 오류**
   - `food.length - 2`는 실제 사용되는 음식의 총량을 반영하지 못한다.
   - 이를 해결하기 위해 `food[1]`부터 마지막 원소까지의 합을 계산하고 홀수 길이로 만드는 방법을 고려했다.
   - 그러나 전체 합이 짝수이더라도 각각의 음식이 동일하게 분배될 수 있다는 보장이 없다.

   반례: `food = [1, 3, 5]`


   | 구분 | 음식 1 | 음식 2 | 합계 |
   |---|---:|---:|---:|
   | 준비된 음식 | 3 | 5 | 8 |
   | 사용 가능한 음식 | 2 | 4 | 6 |
   | 사용하지 않는 음식 | 1 | 1 | 2 |

   - 전체 합을 기준으로 계산한 배열 길이: 9
   - 실제 필요한 배열 길이: 7
2. **삽입 위치 증가 시점 오류**
   - 내부 반복문이 `j = 0`부터 시작하므로 오른쪽에 먼저 음식을 삽입한다.
   - 왼쪽에 음식을 삽입하기 전에 `l`이 증가한다.
   - 따라서 동일한 `l`을 기준으로 좌우 대칭 배치가 이루어지지 않는다.
3. **불필요한 반복 및 인덱스 관리**
   - 배열의 길이를 계산하기 위해 `food` 배열을 한 번 순회한다.
   - 음식을 배치하기 위해 `food` 배열을 다시 순회한다.
   - 좌우 삽입 위치를 관리하기 위한 변수와 조건문이 필요하다.
   - 음식의 배치 결과가 좌우 대칭이라는 특성을 충분히 활용하지 못한다.
4. **리스트 기반 반전 방식의 불필요한 문자열 변환**
   - 음식 번호를 저장하기 위해 `ArrayList<Integer>`를 사용한다.
   - 왼쪽과 오른쪽 문자열을 구성하기 위해 Stream을 통한 문자열 변환이 두 번 필요하다.
   - `StringBuilder`에서도 문자열 반전이 가능하므로 리스트와 Stream을 사용하지 않고 구현할 수 있다.

**개선 방향**

### 1차 개선 — 총량 길이 배열 삽입 방식 수정

1. 배열 길이 계산 방식 수정
   - 음식 종류별로 동일하게 분배할 수 있는 개수를 계산한다.
   - 각 원소가 짝수라면 그대로 더하고, 홀수라면 1을 빼고 더한다.
   - 계산한 총량에 물의 개수인 1을 더하여 배열을 초기화한다.
2. 삽입 순서 수정
   - 내부 반복문의 범위를 `j = 1; j <= qt`로 변경한다.
   - 왼쪽과 오른쪽에 모두 삽입한 이후 `l`을 증가시킨다.

**1차 수정 코드**

```java
import java.util.Arrays;
import java.util.stream.Collectors;

public class FoodFightCompetition {
    public String solution(int[] food) {
        int total = 0;

        for (int i = 1; i < food.length; i++) {
            if (food[i] % 2 == 0) {
                total += food[i];
            } else {
                total += food[i] - 1;
            }
        }

        int[] line = new int[total + 1];
        int l = 0;

        for (int i = 1; i < food.length; i++) {
            int qt = food[i];

            if (qt % 2 != 0) {
                qt -= 1;
            }

            for (int j = 1; j <= qt; j++) {
                if (j % 2 != 0) {
                    line[l] = i;
                } else {
                    line[line.length - 1 - l] = i;
                    l++;
                }
            }
        }

        return Arrays.stream(line)
                .mapToObj(String::valueOf)
                .collect(Collectors.joining());
    }
}
```

### 2차 개선 — 리스트 기반 좌우 대칭 반전 방식

- 음식 배치 결과가 물을 기준으로 좌우 대칭이라는 특성을 활용한다.
- 음식의 총량을 미리 계산하지 않고 리스트를 사용한다.
- `food[i] / 2`의 몫만큼 리스트에 음식 번호를 추가한다.
- 리스트를 문자열로 변환하여 왼쪽 음식 배치를 구성한다.
- `Collections.reverse()`를 사용하여 리스트를 반전한다.
- 반전된 리스트를 문자열로 변환하여 오른쪽 음식 배치를 구성한다.
- 왼쪽 문자열, 물, 오른쪽 문자열을 결합한다.

**2차 수정 코드**

```java
import java.util.*;
import java.util.stream.Collectors;

public class FoodFightCompetition {
    public String solution(int[] food) {
        List<Integer> line = new ArrayList<>();

        for (int i = 1; i < food.length; i++) {
            int qt = food[i] / 2;

            for (int j = 0; j < qt; j++) {
                line.add(i);
            }
        }

        String left = line.stream()
                .map(String::valueOf)
                .collect(Collectors.joining());

        Collections.reverse(line);

        String right = line.stream()
                .map(String::valueOf)
                .collect(Collectors.joining());

        return left + "0" + right;
    }
}
```

### 3차 개선 — StringBuilder 기반 좌우 대칭 반전 방식 (최종 채택)

- `StringBuilder`에서도 `reverse()` 메서드를 제공한다는 것을 확인했다.
- 리스트 대신 `StringBuilder`를 사용하여 음식 번호를 직접 추가한다.
- `food[i] / 2`의 몫만큼 `append()`를 반복한다.
- 왼쪽 문자열과 물을 결합하여 저장한다.
- `StringBuilder.reverse()`를 사용하여 오른쪽 음식 배치를 구성한다.
- 리스트와 Stream을 통한 문자열 변환 과정을 제거한다.
- `String.repeat()`를 활용하여 내부 반복문을 대체할 수도 있지만, Java 버전 호환성과 메서드의 익숙함을 고려하여 반복문 방식을 채택한다.

## 3. 성능 분석

- `N`은 `food` 배열의 길이, `M`은 물을 제외한 실제 사용 음식 수.
- 1차 수정 코드는 총량 계산에 O(N), 배열 배치에 O(N + M), 문자열 변환에 O(M + 1)이 걸려 전체 **O(N + M)**.
- 2차 수정 코드는 리스트 구성에 O(N + M), 리스트 반전과 문자열 변환 및 결합에 O(M + 1)이 걸려 전체 **O(N + M)**.
- 최종 코드는 왼쪽 배치 구성에 O(N + M), 반전과 문자열 결합에 O(M + 1)이 걸려 전체 **O(N + M)**.

## 4. 최종 수정 코드

**개선 의사코드**

1. 왼쪽 음식 배치를 저장할 `StringBuilder` 변수 `left`를 선언하고 초기화한다.
2. `i`는 1부터 `food.length` 미만일 때까지 아래 내용을 반복한다. `i`는 1씩 증가한다.
   - `food[i] / 2`의 몫을 정수형 변수 `qt`에 저장한다.
   - `j`는 0부터 `qt` 미만일 때까지 아래 내용을 반복한다. `j`는 1씩 증가한다.
     - `left.append(i)`를 사용하여 음식 번호를 추가한다.
3. `left`와 물을 의미하는 `"0"`을 결합하여 문자열 변수 `answer`에 저장한다.
4. `left.reverse()`를 사용하여 오른쪽 음식 배치를 구성한다.
5. `answer`와 반전된 `left`를 결합하여 반환한다.

```java
public class FoodFightCompetition {
    public String solution(int[] food) {
        StringBuilder left = new StringBuilder();

        for (int i = 1; i < food.length; i++) {
            int qt = food[i] / 2;

            for (int j = 0; j < qt; j++) {
                left.append(i);
            }

            // Java 11 이상에서는 위 반복문을 repeat()로 대체 가능
            // left.append(String.valueOf(i).repeat(qt));
        }

        String answer = left + "0";

        return answer + left.reverse();
    }
}
```

**학습 내용**

- `StringBuilder.insert()`의 내부 동작 원리와 최악의 시간 복잡도 O(K). 여기서 K는 빌더에 들어 있는 문자 수.
- 배열의 반대편 인덱스에 접근하는 방법: `arr.length - 1 - i`.
- 정수형 배열의 기본 초기화 값은 0이다.
- `StringBuilder.append()`와 `toString()`을 활용한 정수형 배열의 문자열 변환.
- `Arrays.stream()`과 `Collectors.joining()`을 활용한 배열의 문자열 변환.
- `IntStream`의 `mapToObj()`와 `Stream<T>`의 `map()`의 차이.
- `import java.util.*`는 하위 패키지인 `java.util.stream`을 포함하지 않는다.
- 전체 합의 홀수·짝수 여부와 개별 원소의 홀수·짝수 여부는 서로 다른 조건이다.
- 반복문의 시작값에 따라 조건문의 실행 순서가 달라진다.
- 정수 나눗셈의 몫을 활용하여 초과 음식을 제외할 수 있다.
- `Collections.reverse()`는 원본 리스트를 직접 반전한다.
- `StringBuilder.reverse()`는 빌더의 문자 순서를 직접 반전한다.
- `String.repeat(int count)`는 문자열을 지정한 횟수만큼 반복하며 Java 11부터 지원한다.
- `repeat()`로 반복문을 대체하더라도 점근적 시간 복잡도는 동일하다.
- 문제의 대칭성을 활용하면 불필요한 반복문, 조건문, 인덱스 관리를 제거할 수 있다.
- 점근적 시간 복잡도가 동일하더라도 구현 복잡도를 개선할 수 있다.
